# JWT 身份认证详情

一、什么是 JWT

JSON Web Token（JWT）是一种开放标准（RFC 7519），用于在各方之间安全地传输声明。它通常由三部分组成，以点（`.`）分隔，形成 `header.payload.signature` 的格式。JWT 可以在客户端和服务器之间传递，并且可以被验证和信任，因为它经过了签名处理。

二、JWT 的结构

1. 头部（Header）

头部通常包含两部分信息：令牌的类型（通常是 JWT）和使用的签名算法，例如 HMAC SHA256 或 RSA。

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

2. 负载（Payload）

负载部分包含声明（Claims），声明是关于实体（通常是用户）和其他数据的声明。

注册声明：如 `iss`（发行人）、`sub`（主题）、`aud`（受众）等，这些是预定义的声明，但不是强制使用的。
公开声明：由各方自由定义。
私有声明：在同意使用的一方之间定义。

```json
{
  "sub": "1234567890",
  "name": "John Doe",
  "iat": 1516239022
}
```

3. 签名（Signature）

为了创建签名部分，需要使用编码后的头部、编码后的负载、一个秘钥（secret）和头部中指定的签名算法。

```plaintext
HMACSHA256(
  base64UrlEncode(header) + "." +
  base64UrlEncode(payload),
  secret)
```

三、JWT 的工作流程

1. 用户登录

用户向服务器发送登录请求，提供用户名和密码。服务器验证用户的凭证，如果验证通过，服务器会创建一个 JWT。

```javascript
const jwt = require("jsonwebtoken");
const secretKey = "yourSecretKey";
const payload = { userId: 123, username: "john_doe" };
const token = jwt.sign(payload, secretKey, { expiresIn: "1h" });
```

2. 服务器返回 JWT

服务器将生成的 JWT 返回给客户端，通常是在响应的头部或响应体中。

3. 客户端存储 JWT

客户端接收到 JWT 后，通常将其存储在本地（如 localStorage 或 sessionStorage）。

4. 客户端后续请求

客户端在后续的请求中，将 JWT 包含在请求的头部中，通常使用 `Authorization` 头部，格式为 `Bearer <token>`。

```javascript
const token = localStorage.getItem("jwtToken");
fetch("https://api.example.com/data", {
  headers: {
    Authorization: `Bearer ${token}`,
  },
});
```

5. 服务器验证 JWT

服务器接收到请求后，从请求头部中提取 JWT，并使用相同的秘钥和签名算法对其进行验证。

```javascript
const jwt = require("jsonwebtoken");
const secretKey = "yourSecretKey";
const token = req.headers["authorization"].split(" ")[1];
jwt.verify(token, secretKey, (err, decoded) => {
  if (err) {
    // 验证失败，返回错误响应
  } else {
    // 验证成功，继续处理请求
    const userId = decoded.userId;
  }
});
```

四、JWT 的优缺点

1. 优点

无状态：JWT 是无状态的，服务器不需要在会话中存储任何信息，这使得服务器可以更容易地进行扩展。
跨域支持：由于 JWT 可以通过 HTTP 头部传输，因此可以轻松地在不同的域之间使用。
可扩展性：负载部分可以包含任意的声明，因此可以根据需要扩展 JWT 的功能。

2. 缺点

安全性风险：如果 JWT 的秘钥泄露，攻击者可以伪造 JWT。此外，由于 JWT 通常存储在客户端，可能会受到 XSS 攻击。
令牌大小：JWT 可能会比较大，尤其是当负载部分包含大量信息时，这会增加请求的大小。
难以撤销：一旦 JWT 被发放，就很难在其过期之前撤销它。

五、使用场景

身份验证：在用户登录后，服务器可以发放一个 JWT，客户端在后续的请求中携带该 JWT 进行身份验证。
信息交换：JWT 可以安全地在各方之间传输信息，因为它经过了签名处理，可以确保信息的完整性和真实性。
